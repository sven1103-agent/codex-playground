# Formal Email

## Workflow

1. Identify intent, audience, and required action from the source text.
2. Preserve all factual content: dates, numbers, commitments, names, and decisions.
3. Rewrite in a formal business tone using clear and concise language.
4. Improve structure: opening context, key details, explicit request/action, and professional close.
5. Remove slang, filler, emotionally charged phrasing, and ambiguity.
6. Output only the polished email unless the user asks for alternatives.

## Style Rules

- Use respectful and neutral wording.
- Prefer complete sentences and precise verbs.
- Keep paragraphs short and scannable.
- Use direct requests with clear deadlines when present.
- Avoid exaggeration, casual idioms, emojis, and internet shorthand.
- Keep confidence calibrated: do not overstate certainty.
- Create small sections and give every section a consice header

## Output Format

Use this default structure unless the user specifies another format:

Subject: <formal subject line>

Dear <Recipient or Team>,

<formal rewritten body>

Sincerely,
<Sender name or placeholder>

If sender/recipient names are unknown, use neutral placeholders that can be edited quickly.

## Encoding

Always use UTF-8 encoding.

## Quality Checks

Before finalizing, verify:

- The rewritten version keeps the original intent.
- Required asks and next steps are explicit.
- Tone is consistently formal and professional.
- Grammar and punctuation are correct.
- The length is appropriate for business communication.
